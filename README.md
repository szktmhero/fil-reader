# FileReader - 大容量ログ・CSVビューア (ベータ版)

`FileReader` は、10GBクラス（数千万〜数億行）の超大容量なログファイルやCSV・TSV・DATファイルを、メモリ不足（OOM）や画面のフリーズを起こすことなく高速に閲覧・キーワード検索できるWindowsデスクトップアプリケーション（WPF）です。

---

## 🚀 主な機能と特徴

1. **超大容量データのハンドリング (10GB+ 対応)**
   - ファイルをメモリに一括ロードするのではなく、一時SQLiteデータベースへストリーミング（バルクインサート）し、表示・検索に必要な分だけをオンデマンドで取得します。
2. **データ仮想化 (Data Virtualization) x UI仮想化 (UI Virtualization)**
   - WPF標準の `DataGrid` 仮想化機能と連携するカスタム `VirtualizingList` (ページキャッシュ機能付き) を実装。
   - 数億行あってもメモリ使用量は **500MB以下** に抑えられ、スクロールも非常に滑らかです。
3. **設定ファイルによる区切り文字の動的対応**
   - アプリ配置フォルダ内の設定ファイル `config.json` にて、対象ファイルの拡張子、区切り文字（カンマ `,`、タブ `\t`、パイプ `|` など）、ヘッダーの有無、列定義を柔軟に設定可能。
4. **高速キーワード検索**
   - インポート完了後、バックグラウンドスレッドで自動的に全列にインデックス（`CREATE INDEX`）を構築。
   - インデックスが効く「前方一致のみ（超高速）」や、任意の列指定検索、全列に対する曖昧検索（`LIKE '%word%'`）に対応。
5. **洗練されたダークテーマ UI**
   - ガラス調（Glassmorphism）の要素、グラデーションを活かしたモダンで高級感のあるダークモード。
   - 直感的なドラッグ＆ドロップによるインポートエリア、複数ファイルを同時に展開できるタブベースUI。
   - インポート中の処理速度（行数/秒）や進捗をリアルタイム表示。

---

## 🛠 システム要件

- **OS:** Windows 10 / 11
- **ランタイム:** .NET 9.0 SDK または .NET 9.0 ランタイム (WPFサポート)

  - `Microsoft.Data.Sqlite` (SQLite接続)

  - `Microsoft.Extensions.Configuration.Json` (JSON設定ロード)

## 📂 設定方法 (`config.json`)

アプリケーション実行フォルダ（またはプロジェクトフォルダ）の `config.json` にて、ログの拡張子や区切り文字を定義します。

```json
{
  "LogFormats": [
    {
      "Extension": ".csv",
      "Delimiter": ",",
      "HasHeader": true
    },
    {
      "Extension": ".tsv",
      "Delimiter": "\t",
      "HasHeader": true
    },
    {
      "Extension": ".log",
      "Delimiter": "\t",
      "HasHeader": false,
      "Columns": [ "Timestamp", "Level", "Logger", "Message" ]
    },
    {
      "Extension": ".dat",
      "Delimiter": "|",
      "HasHeader": false,
      "Columns": [ "Id", "Name", "Value", "Timestamp" ]
    }
  ]
}
```

- **`Extension`**: ファイルの拡張子（小文字）。
- **`Delimiter`**: 区切り文字。タブは `\t`、パイプは `|` など。
- **`HasHeader`**: ファイルの1行目を列ヘッダーとして扱う場合は `true`、そうでない場合は `false`。
- **`Columns`**: `HasHeader` が `false` の場合に適用されるデフォルトの列名リスト。指定しない場合は自動的に `Column_1, Column_2...` が生成されます。

## 🏗 技術設計と内部アーキテクチャ

```
[ログファイル]
   │
   ▼ (Span<T> カスタムパーサー または CsvHelper)
[SQLite 一時データベース (temp_logs_*.db)]
   │
   ├─► (バックグラウンド: CREATE INDEX による検索最適化)
   │
   ▼ (オンデマンド取得: LIMIT 100 OFFSET ... / ページングキャッシュ)
[VirtualizingList: IList]
   │
   ▼ (UI仮想化: DataGrid recycling)
[WPF DataGrid] (メモリ消費極小・超高速スクロール)
```

1. **高速インポート:**
   `SQLiteTransaction` を用いて、100,000行単位でまとめてコミットすることで、ディスクへのI/O負荷を劇的に下げ、数千万行を数分でDB化します。SQLite側のチューニングとして `PRAGMA cache_size` や `mmap_size`、自動採番オーバーヘッドの排除 (`AUTOINCREMENT` の削除) も行っています。
2. **破損行対策 (堅牢性):**
   列数が足りない行や不正なデータがある場合でも、該当部分を空文字として補完し、全体の読み込みを極力続行します。
3. **自動クリーンアップ:**
   タブを閉じた際、またはアプリケーションを正常・異常終了した際の一時DBファイルは自動的に物理削除されます。また、次回起動時に前回の残存ファイルを自動検知してクリーンアップします。

### 🚀 フィーチャーフラグによる極限最適化 (`UseFastSpanParser`)
ソースコード (`FileReader/Services/LogDatabase.cs`) 内に、パース処理の内部エンジンを切り替えるフィーチャーフラグが用意されています。

```csharp
// フィーチャーフラグ: Span<T>を用いた自作の高速パーサーを使用するか（CsvHelperの代替）
public bool UseFastSpanParser { get; set; } = true;
```

- **`true` (デフォルト - 限界突破モード)**:
  `CsvHelper` の内部バッファリングを完全にバイパスし、`ReadOnlySpan<char>` を用いた自作のゼロアロケーション指向パーサーでファイルを読み込みます。ガベージコレクション（GC）の負荷や例外ハンドリングのオーバーヘッドを極限まで削ぎ落としており、数GBクラスの巨大ファイルのインポート速度を最大化します。
- **`false` (安全・堅牢モード)**:
  実績のある `CsvHelper` を使用します。改行を含む複雑なクォーティング処理など、エッジケースを含む特殊なCSVファイルを厳密に読み込む必要がある際はこちらを有効にしてください。

## ファイル分析・保存パターン

ファイルの読み込み後、検索バーの **「分析・パターン...」** から分析画面を開きます。

- **SQL**: `log_data` に対する単一の `SELECT` / `WITH` を実行します。元ファイルの検索条件はSQLに自動適用されません。必要なら `WHERE` を指定してください。
- **簡易集計**: グループ列（任意）、`COUNT` / `SUM` / `AVG` / `MIN` / `MAX`、集計列を選び「SQLを作成」→「実行」。`COUNT` は行数、それ以外は数値集計です。
- **保存パターン**: 名前を入力し「SQL＋グラフを保存」または「現在の検索条件を保存」。一覧から「呼び出す」で復元します。復元時の自動実行はありません。同じ種類・名前は確認後に上書きできます。
- **検索条件**: 元の検索画面で設定した条件を保存します。呼び出した後は分析画面を閉じ、元画面で内容を確認して検索してください。必要な列がない場合は復元せずエラーを表示します。
- **グラフ**: 実行後にX列・数値のY列を選び、棒／折れ線を指定して「グラフを表示」。グラフタブで確認できます。設定はSQLパターンに保存されます。結果列が変わった場合は選び直してください。
- **CSV**: 「表示結果をCSV出力」で、最後に成功した問い合わせの表示結果を出力します。

例えば `Level` ごとの件数:

```sql
SELECT Level, COUNT(*) AS 件数
FROM log_data
GROUP BY Level
ORDER BY 件数 DESC;
```

数値列 `Amount` をカテゴリ別に合計する例:

```sql
SELECT Category, SUM(safe_number(Amount)) AS 合計
FROM log_data
GROUP BY Category
ORDER BY Category;
```

### データの扱いと初版の制限

- 元の列はSQLiteのTEXT型です。数値計算には `safe_number(列名)` を使います。空欄はNULL、不正な数値はエラーになります。小数点は `.`、桁区切りや通貨記号は受け付けません。変換結果は倍精度浮動小数点で、厳密な金額計算向けではありません。
- 分析は独立した読み取り専用接続で実行します。UIをブロックせず、中断ボタンと60秒の実行上限があります。
- 結果の表示・CSV出力は最大10,000行。超えた場合は明示します。SQLの集計自体は全対象行に対して実行されます。
- グラフは結果200行まで。行順をそのままX軸の等間隔カテゴリとして使用します。時系列はSQLで日付順に並べてください。NULLや非数値のY値は描画エラーとして表示します。
- パターンは `%LOCALAPPDATA%\FileReader\patterns.json` に保存され、別ファイルや再起動後にも使えます。SQL・検索語は平文です。元データや問い合わせ結果は保存しません。
- SQLで存在しない列を参照した場合は、実行時にSQLiteのエラーを表示します。
- CSV読み込みは引用符内の区切り文字・改行を扱えるCsvHelperを標準にしています。従来の簡易パーサーとは読み込み速度が変わる可能性があります。
- 初版は単一ファイルの分析です。外部DB接続、複数ファイルJOIN、ダッシュボード、グラフ画像出力は含みません。

### 検証

```bash
dotnet build FileReader.sln
# UIに依存しない実SQLite・ファイル入出力の回帰チェック
dotnet run --project FileReader.Tests
```

Windowsでの画面確認:

1. CSVを開き、従来の検索・検索結果出力が使えることを確認。
2. 分析画面で簡易集計SQLを生成・実行し、表とCSVの件数・値を確認。
3. 棒／折れ線を描画し、負数、軸ラベル、ホバー時の値を確認。
4. SQL＋グラフと検索条件をそれぞれ保存。アプリ再起動後・別ファイルで呼び出し、実行されず復元されることを確認。
5. 必要な列がないファイルでのエラー、不正なSQL、中断、表示件数上限を確認。
6. グラフタブやウィンドウのサイズ変更、実行中の閉じる操作を確認。
